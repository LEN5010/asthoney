# 基于多智能体的生成式欺骗蜜罐网与态势感知系统

个人课程设计报告

第14组  132-刘毅凡

## 1 主要工作与工程取舍

我负责项目的总体设计、核心模块实现和联调，前端重构与最终交付也由我统筹。这个项目不是把几个模型接到页面上，而是把诱捕入口、会话状态、意图判断、存储和展示组织成一条能回看的链路。外层 SSH 使用真实握手并免登录凭据，进入后的命令则限制在仿真主机世界里。这样既保留了客户端交互体验，又避免把攻击载荷变成宿主机上的真实命令。报告中的模型、规则与模拟处置需要分开说明，不能依靠“智能体”这一名称掩盖实际实现。

## 2 设计中的主要问题

连续交互比单次返回更难处理。攻击者在一台主机上创建文件，再进入另一台主机，回来后应当仍能找到此前的修改。如果只维护当前主机的一份状态，横向移动会覆盖原有世界。本项目以会话为单位保存多主机快照，把当前资产与访问过的主机分开管理。读取凭证只增加证据，不直接触发换主机；内层 ssh 才改变活动主机。这些边界让行为能够被测试，也便于解释拓扑变化。

## 3 程序调试与验证思路

本轮验收暴露了两个容易被演示成功掩盖的问题。一个是首页把多个请求放在同一个失败分支里，告警接口短暂异常就会使拓扑也不更新；另一个是启动脚本先调用系统 Python，再调用虚拟环境中的服务程序，造成环境检查与实际启动不一致。解决思路分别是按面板隔离错误，以及在启动前确定唯一解释器。对问题的判断不能只看页面是否打开，还要检查错误出现后其他区域是否继续工作、修复后是否存在可重复的验证步骤。

## 4 界面与项目结果分析

旧界面把事件、统计、拓扑和说明放进相似卡片，所有区域都在争夺注意力。最终版本以拓扑和会话为中心，指标压缩成摘要条，回放详情改成标签切换，清理入口放入维护区。浅色样式只是表面变化，更重要的是操作顺序清楚、错误有解释、数据来源可追溯。最终代码通过九十三项 Python 测试；独立 Agent 完成三十四条命令、三台主机的探索并返回，网页可回放六十八条输入输出事件。这个结果说明已覆盖场景能够复现，并不等于系统具备生产环境的容量和安全保证。

## 5 课程收获与后续改进

我在项目中更重视状态边界与交付证据，而不是继续增加功能名称。生成式输出需要可靠的确定性分支兜底，图数据库中的关联关系需要与页面显示一致，运行文档中的命令需要在干净目录执行。后续改进应优先完善虚拟命令语义、线索之间的一致性和更细粒度的技术映射，并为实时事件增加持久化机制。团队协作方面，应当把界面校验、异常测试和材料复核分成可验证的小任务，让每个成员根据自己的完成记录写报告，而不是在最后阶段用同一份总结替换姓名。
