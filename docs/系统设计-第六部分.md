# 第六部分 系统设计（课设正文底稿）

本文与当前代码对齐，供写入工程项目开发报告第六部分。外层 2222 是真实 SSH 握手和认证。壳内命令、内层横向移动仍是仿真，不在宿主机执行。隔离为模拟动作。MCP 为面向 Agent 的 HTTP 工具面。

## 6.1 总体架构

系统按四层部署在同一台演示机上。

1. **诱捕接入层**：`TrafficEngine` 在可配置端口（默认 2222/2323）监听。2222 用真实 SSH 协议完成握手，主机密钥和登录私钥都由蜜罐在 `var/ssh/` 生成。认证通过后按行把命令交给主智能体。2323 仍是原始 TCP 横幅。
2. **智能决策层**：`MainAgent` 用 LangGraph 状态图完成 `analyze → plan → route → engage → critique`。分析员给出意图，欺骗规划员决定留在本机、走向下一跳、只漏线索或只回横幅，终端演员按该计划生成输出，护栏只检查输出能不能交出去。图执行结束后，抢占式控制根据意图等级写告警并做模拟隔离。MCP 风格陷阱工具一经调用即记 critical 告警。
3. **数据存储层**：Neo4j 保存 Asset、Session、Identity、Event、Intent、Alert、Action 及可达/访问关系。横向移动等意图会 JIT 合成下一跳诱饵资产。
4. **控制展示层**：FastAPI 提供 REST 与 `/ws/events`。Web 面板包含总体态势、会话回放、ATT&CK 观测矩阵与攻击者画像。敏感写接口要求 `X-Admin-Token`。

运行时依赖：Python 3.11+、Neo4j 5.x、可选 OpenAI 兼容大模型网关。大模型未配置时，终端仿真与研判走确定性/启发式分支，核心诱捕与回放不受影响。

## 6.2 一次攻击的数据流

```
攻击者 ssh -i var/ssh/lure_ed25519 -p 2222 svc-backup@边缘主机
  → TrafficEngine 消毒/超时
  → MainAgent.handle_payload
       1. 落库 Session / Event
       2. LangGraph.analyze  推断意图（先放在状态里，不落第二条）
       3. LangGraph.plan     确定性欺骗策略与要埋的线索
       4. LangGraph.route    静态横幅、留在当前资产，或合成/选择下一跳
       5. LangGraph.engage   SubAgent 按计划生成终端输出
       6. LangGraph.critique 检查输出；每条命令只写一条 Intent，并写 Decision 轨迹
       7. 抢占式控制         Alert + 模拟隔离 Action
  → 写回连接
  → EventBus 广播 session.activity / intent.detected / agent.trace / alert.raised
  → 面板 WebSocket 立即刷新，REST 提供回放与矩阵/画像
```

MCP 陷阱不走诱捕端口：`POST /mcp/tools/{name}` → `MainAgent.handle_mcp_trap` → 403 + critical 告警 + 模拟隔离。

## 6.3 主智能体状态图

状态图有五个节点。规划员和护栏是确定性的，终端演员可以调用大模型，模型不可用时回退到伪终端。答辩时说明这是主从编排加可见决策，不是多个大模型互相辩论：

| 节点 | 角色 | 职责 | 下一步 |
| --- | --- | --- | --- |
| `analyze` | 分析员 | 规则推断意图类别、置信度、是否需要子智能体 | 固定到 `plan` |
| `plan` | 欺骗规划员 | 选择 deepen / pivot / stall / banner，并写下一行要露出的线索和中文理由 | 固定到 `route` |
| `route` | 路由 | 横幅直接结束；发现和读凭证留在当前主机（入口网关先进入预置邻居）；只有 ssh 横向才进入下一跳 | `engage` 或 `critique` |
| `engage` | 终端演员 | 按目标资产创建/复用 SubAgent，把规划线索写进终端输出 | `critique` |
| `critique` | 输出护栏 | 判断输出是否可下发；每条命令只写一条 `Intent`，并把四角色轨迹写入 `Decision` | 结束 |

抢占式告警与隔离在图外执行，避免把副作用缠进状态图，也便于降级和测试。每条轨迹通过 `agent.trace` 推到态势面板。

读 `/etc/passwd` 或 `db.env` 记为凭证访问，策略是 deepen，不因为这条命令换主机。`ssh user@10.0.5.2` 才换成目标主机的世界，并回一段非交互公钥登录记录。会话快照用 `hosts` 保留到过的每一台，当前主机仍放在快照顶层，旧面板只读顶层也不会丢当前目录。

## 6.4 图数据模型

主要节点：`Asset`、`Session`、`Identity`、`Event`、`Intent`、`Alert`、`Action`。

主要关系：

- `Identity -[:INITIATED]-> Session -[:TARGETS]-> Asset`
- `Session -[:OBSERVED]-> Event -[:TOUCHED]-> Asset`
- `Session -[:VISITED]-> Asset`（含 JIT 节点）
- `Asset -[:CAN_REACH {vector}]-> Asset`
- `Action -[:CONTAINS]-> Identity`（模拟隔离）

种子拓扑：两个边缘网关 → `web-pivot-01` → `db-replica-01` → `oss-sync-bridge`。JIT 节点带 `jit_synthesized=true`，清空历史时删除，预置迷宫保留。

## 6.5 态势分析

- **ATT&CK 矩阵**：意图类别与告警类型映射到本系统可观测的技术子集（如 T1082、T1021.004、T1105）。不追求完整企业矩阵。
- **威胁画像**：按来源 IP 聚合。分数 = 意图严重度(45) + 攻击链深度(25) + 告警强度(20) + 自动化特征(10)，每项回传明细。
- **实时事件**：进程内 EventBus，订阅者队列满时丢旧保新；新连接先收回放缓冲。

## 6.6 降级与安全控制

| 条件 | 行为 |
| --- | --- |
| 未配置或超时大模型 | 解释器按会话世界执行 pwd、cd、ls、cat、find、grep、head、tail、wc、echo、管道、重定向和 bash -c。目录里列出来的文件都有固定正文。不接管的命令才回退。跳板、数据库、对象存储各有一份世界 |
| 答辩播放 `/demo/theater` | 每步 1.8 秒，高于 1.5 秒的自动化判定阈值，播放本身不会被标成非人代理 |
| 危险命令 / 护栏命中 | 只返回仿真拒绝，不在宿主机执行 |
| 隔离模式 `simulate` | 只写 Action，不改真实网络 |
| 控制面无令牌 | `/simulate`、`/history/purge`、研判控制返回 401 |
| 内层 ssh | 换到目标主机的世界，并回一段非交互公钥登录记录。上一台主机的新建文件留在同一份快照的 hosts 里 |
| 进程重启 | 从已落库的 Action/Alert 恢复隔离集合与陷阱计数。会话世界保留最后一次快照，活连接里的解释器状态不恢复 |
| 公开回看世界 | `/sessions/{id}/world` 默认打码口令和私钥。请求头带对 `X-Admin-Token` 才返回完整诱饵 |

## 6.7 主要接口

控制面：`/healthz` `/status` `/sessions*` `/sessions/{id}/decisions` `/alerts` `/actions` `/graph/overview` `/attack/matrix` `/profiles` `/timeline` `/ws/events`。  
管理写接口：`/simulate` `/demo/theater` `/history/purge` `/sessions/{id}/analysis/controls`。  
诱捕面：TCP 2222/2323，REST `/mcp/tools*`，以及 JSON-RPC `POST /mcp`。
